# Project Organization Postman Guide: Remote Supabase

This guide explains how to run the project organization Postman collection against a **dedicated remote Supabase test project**. It assumes you are new to Postman and Supabase. You do not need Docker, and you must not start local Supabase.

## Can I run the collection all at once?

**Yes. This collection is designed to run all 27 requests in one Collection Runner session.** Select the 336 environment and run the `336-project-organization` folder in its existing order. Login requests and setup requests capture the session tokens, James's Inbox ID, and IDs for the projects created during this run. The successful reorder request also records the expected order for the following assertion. There are no manual copy/paste steps.

The order matters: the later favorite/archive/reorder requests use IDs generated by earlier requests. Do not reorder or skip the setup requests. The collection leaves its created project rows in the remote database, so use an isolated test project.

## Important safety warning

Use a **dedicated, isolated Supabase project for testing**. Do not use production, a teammate's project, or a shared development project. These tests create projects, change their favorite/archive/order fields, and leave the created projects in the database.

Never run **Supabase: Reset REMOTE DB (destructive)** for this guide. It drops and recreates the linked remote database. Use **Supabase: Seed Remote (no reset)** for fixtures; it does not reset the whole database, but it does create/update the seeded users and other seed data.

## What the collection uses

The collection logs in as James and Harvey, who are created by `supabase/seeds/001_users.sql`:

| Account | Email | Password |
| --- | --- | --- |
| James | `james@example.com` | `password123` |
| Harvey | `harvey@example.com` | `password123` |

James's Inbox project comes from `supabase/seeds/002_inbox_projects.sql`. Postman does not create these accounts or the Inbox. The backend reads user/project rows from PostgreSQL and checks credentials through Supabase Auth, so `DATABASE_URL`, `SUPABASE_URL`, and `SUPABASE_SERVICE_ROLE_KEY` must all refer to the **same test project**.

## Before you begin

You need VS Code, Postman, Node.js 22 or later, and access to a dedicated remote Supabase test project. Docker Desktop is not needed. If the repository dependencies are not installed, run **📦 Install All Dependencies** from **Tasks: Run Task**.

## 1. Link and prepare the remote test project

1. Sign in to the Supabase Dashboard and open the dedicated test project. Note its name and project reference. Do not continue if you cannot distinguish it from production or shared development.
2. In VS Code, choose **Terminal > New Terminal**. Confirm that the terminal is at the repository root, the folder containing `package.json` and `supabase`. If needed, enter:

   ```powershell
   cd C:\Users\Matthew\source\repos\project-team-404
   ```

3. Open the Command Palette with `Ctrl+Shift+P`, choose **Tasks: Run Task**, and run **🔐 Supabase: Login**. Follow the browser sign-in steps.
4. Run **🔗 Supabase: Link Project**. Select the dedicated test project and verify its name/reference before confirming. Enter its database password directly into the terminal if prompted; do not put it in Postman or a checked-in file.
5. Run **📊 Supabase: Check Migration Status**. If repository migrations are pending, run **📤 Supabase: Push Migrations**. If the CLI suggests destructive reset/replacement, cancel and confirm with the project owner.
6. Run **🌱 Supabase: Seed Remote (no reset)**. Each seed file runs against the linked project and reports `SUCCEEDED` or `ERROR` based on SQL execution. Stop if any seed reports `ERROR`.

The seed task is not a full database reset, but it sets seeded passwords to `password123` and updates fixture rows. Run it only against the dedicated test project.

## 2. Configure the backend

Postman talks to the Express API running on your computer. The API connects to the remote test project.

1. In VS Code's Explorer, open `backend/.env`. If it does not exist, run **🛠️ Setup: Create Environment Files** from **Tasks: Run Task**.
2. Set `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, and `DATABASE_URL` to values for the same remote test project. Set `DIRECT_URL` to its direct database URI. Use the Supabase Dashboard values, not the example placeholders in `backend/.env.example`.
3. Set or confirm `NODE_ENV=development`, `PORT=3000`, `WEB_APP_URL=http://localhost:4200`, and `CORS_ALLOWED_ORIGINS=http://localhost:4200`.
4. These project tests do not send email. If you have no other reason to configure Brevo, remove or comment out `BREVO_API_KEY` and `BREVO_SENDER_EMAIL`. Do not leave empty assignments; the backend rejects supplied empty strings.
5. Save `backend/.env` with `Ctrl+S`. If the backend is already running, stop it with `Ctrl+C`; start it again in the next section.

Keep the service-role key and database URI private in `backend/.env`. Do not put them in the Postman environment. `SUPABASE_TEST_*` variables are for automated test runners, not these manual Postman requests.

## 3. Start the frontend and API

1. In VS Code, press `Ctrl+Shift+P`, choose **Tasks: Run Task**, and select **🚀 Dev: Start All**. This starts the frontend and backend in parallel.
2. Keep the task running while using Postman. Wait for the backend terminal to report that the server is listening on port `3000`; the frontend runs on port `4200`.
3. Open `http://localhost:3000/health` in a browser to confirm that the API is reachable.

## 4. Import the Postman files

This folder contains:

- `Project-Team-404 API - 336-project-organization.postman_collection.json`
- `Project-Team-404 Local (336-project-organization).postman_environment.json`

The collection contains requests and assertions; the environment contains `baseUrl`, seeded account details, and runtime variables.

1. Open Postman and choose your workspace.
2. In Windows File Explorer, open:

   ```text
   C:\Users\Matthew\source\repos\project-team-404\tests\postman\336-project-organization
   ```

3. Select both JSON files: click one, hold `Ctrl`, and click the other.
4. Drag both files into the Postman window and drop them. Confirm the import preview. Alternatively, click **Import**, choose **Files**, select both files, and confirm.
5. In Postman's left sidebar, confirm the collection appears as **Project-Team-404 API - 336-project-organization** and the environment as **Project-Team-404 Local (336-project-organization)**.

## 5. Select and check the environment

The collection's **Variables** tab may be empty; its requests use the selected environment.

1. Click the environment selector near Postman's upper-right corner and select **Project-Team-404 Local (336-project-organization)**. Confirm it has a check mark under **Environments** in the left sidebar.
2. Open the environment variables and check **Current value**:

   | Variable | Expected value/action |
   | --- | --- |
   | `baseUrl` | `http://localhost:3000/api` |
   | `seedPassword` | `password123` |
   | `jamesEmail` | `james@example.com` |
   | `harveyEmail` | `harvey@example.com` |
   | `token`, `tokenB` | Leave blank; login requests set them. |
   | `inboxProjectId` | Leave blank; James's `/auth/me` request captures it. |
   | `projectId`, `projectId2`, `projectIdB` | Leave blank; setup requests capture them. |
   | `expectedOrder` | Leave blank; the reorder request saves it. |

3. If `baseUrl` differs, set it to `http://localhost:3000/api`. This is the local API address, not the remote Supabase URL.
4. Do not manually fill the generated variables. Save the environment if Postman shows a **Save** button or unsaved-changes indicator.

## 6. Run all requests in Collection Runner

1. Confirm the backend is running and the 336 environment is selected.
2. In the **Collections** sidebar, expand **Project-Team-404 API - 336-project-organization**.
3. Click **Run** on the collection, or click the collection's `...` menu and choose **Run**.
4. In Collection Runner, select the **336-project-organization** folder if asked. Confirm **Project-Team-404 Local (336-project-organization)** is the selected environment.
5. Keep all 27 requests selected and in their existing order.
6. Click **Run 336-project-organization**. Wait for the run summary.

Some requests are expected to return `400`, `401`, or `404`. Those are intended negative cases; the test passes when the response matches the expected status and assertions.

### Send requests one at a time for troubleshooting

You can click each request in the expanded folder and press **Send** instead. Still use the same order:

- Send the two login requests before requests that require `token` or `tokenB`.
- Send **Capture James Inbox ID** before the Inbox archive test.
- Send all three project setup requests before favorite/archive/reorder requests.
- Send **Reorder projects in requested order** before the list assertion that compares against `expectedOrder`.

## 8. Data left behind and common failures

The collection creates three remote project rows and does not delete them. It returns them to active/unfavorited state after its tests, but it leaves the successful reorder state on the two James test projects. A later run creates new test projects and works with those IDs. This is expected in an isolated test project; do not use production or shared data.

| Postman result | Check this |
| --- | --- |
| Connection refused or no response | Confirm the backend is running and `baseUrl` is `http://localhost:3000/api`. |
| A seeded login returns `401` | Confirm the test project was seeded, `seedPassword` is `password123`, and `SUPABASE_URL`/`DATABASE_URL` target the same project. |
| A request URL contains an empty project ID | An earlier login/setup request did not pass in this Runner session. Start the folder from request 1 and keep the order. |
| Inbox archive does not return `400` | Confirm request 3 captured James's Inbox ID and the remote project has the Inbox fixture. |
| Order assertion fails | Run the reorder request before the list check and do not skip setup requests. |
| Backend exits after removing Brevo | Remove/comment out Brevo settings instead of leaving empty assignments, then restart the backend. |
| Migration or seed task reports `ERROR` | Stop and inspect the CLI output and linked project. Do not use the destructive remote reset task. |

No profile or password changes are made by this collection. The remote project will retain the three organization-test projects created during each run.
